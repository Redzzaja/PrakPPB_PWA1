# PRD — MyMusikgwe (PWA Lab)

## 1. Overview
A minimal Progressive Web App (PWA) built as a teaching lab for the PPB
(Pemrograman Perangkat Bergerak) course. It is a simple **music player UI**
(mock, no real audio) that demonstrates the three pillars of a PWA:
**application shell**, **web app manifest**, and **service worker** — on a
modern **React + Vite + JavaScript + Tailwind CSS** stack.

## 2. Goals
- Show a working, **installable** PWA (add to home screen) with an app shell,
  manifest, and offline-capable service worker.
- Follow React/Vite **best practices** (component structure, Vite PWA plugin,
  proper icon set, Lighthouse-friendly).
- Stay **simple and readable** so students can trace every piece.

## 3. Non-Goals
- No real audio playback, backend, auth, or database.
- No state management library (React state is enough).
- No TypeScript (per request: JavaScript).
- No offline data sync — offline only serves the cached shell.

## 5. Functional Requirements
1. **App shell** — persistent header, nav, content area, player bar, footer.
   Only the content area changes between views.
2. **Views** — `Home` (track list) and `About` (lab info). Navigation is
   client-side state, so the service worker caches a single shell.
3. **Music player UI (mock)** — a static list of tracks (title/artist/duration)
   plus a player bar with prev / play-pause / next. No audio: buttons toggle
   local UI state only.
4. **Web app manifest** — generated by the plugin: `name`, `short_name`,
   `description`, `theme_color`, `background_color`, `display: standalone`,
   `start_url`, and icons (192 / 512 / maskable).
5. **Service worker** — Workbox-powered: precache the shell and static assets,
   serve offline fallback for navigations. Auto-registered with
   `registerType: 'autoUpdate'`.
6. **Icons** — app icon (SVG + PNG 192/512/maskable/apple-touch).

## 6. Non-Functional Requirements
- **Installable**: passes Chrome installability criteria (manifest + SW +
  icons + HTTPS or localhost).
- **Offline**: full shell loads with no network after the first visit.
- **Lighthouse PWA ≥ 90** on localhost / deployed.
- **Fast first paint**: minimal JS, no heavy dependencies.

## 7. Project Structure
```
public/
  icon.svg
  pwa-192x192.png  pwa-512x512.png  apple-touch-icon.png
src/
  main.jsx                 # renders <App/>
  App.jsx                  # app shell + view state
  components/
    PlayerBar.jsx          # mock player controls
    TrackList.jsx          # static track list
  views/
    Home.jsx  About.jsx
  data/tracks.js           # mock track data
  index.css                # tailwind import
index.html                 # theme-color meta, title
vite.config.js             # react + tailwind + VitePWA plugins
```

## 8. Acceptance Criteria
- `npm run dev` and `npm run build && npm run preview` both work.
- Build outputs `manifest.webmanifest` and `sw.js` in `dist/`.
- App is installable and works offline in `preview` (or deployed).
- All three PWA pillars are present and explained in the README.
- `npm run lint` passes.

## 9. Out of Scope
- Real audio, backend data, push notifications, background sync, deployment/CI.
